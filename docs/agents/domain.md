# Domain Docs

This is a single-context repository. Engineering skills should use the repository's domain documentation when exploring or changing domain behavior.

## Before exploring

- Read `GLOSSARY.md` at the repository root when it exists.
- Read relevant records in `docs/adr/` when they exist.
- If these files are absent, proceed silently. Create them only when a domain term or architectural decision needs to be recorded.

Use glossary terms consistently in code, tests, issues, and design notes. If a change conflicts with an existing ADR, identify the conflict rather than silently replacing the decision.
